## Scientific rules

- Call this DynaHarness-inspired independent implementation until all parity
  requirements are verified. Do not claim 17.5 → 75.2 was reproduced.
- A 592/800 vs 511/800 source comparison concerns **fixed evolved capabilities on
  development states**. It is not the new-state headline. Removing analytic
  contact skills drops the source result to 133/800. A monitor cannot replace
  those skills. See primary source audit.
- Keep initial states, actual state hashes, motor checkpoint, planner, observation
  access, action budgets, reset semantics and success predicate comparable.
- `policy_seed` is a requested trial identifier. The native adapter does NOT
  control the upstream stochastic policy sampler. Do not call these RNG-matched.
- Default actor access is sensor-style RGB-D/proprioception. `privileged_sim`
  is a separately labeled diagnostic, never merged with sensor results.
- Sensor backprojection returns a surface point, not a perfect object center,
  collision-free grasp, hidden joint axis, or installed-part pose.
- Never translate EEF arrival, gripper closure, or a model's "done" into native
  success. Command completion and task success are different.
- Never force a first attempt to fail for a dramatic video. Record genuine errors.
- Do not tune on the final test manifest or import task-specific upstream memories
  into a nominally memory-free baseline.
- Preserve denominators, missing cases, infrastructure errors and failed runs.
- Keep the qualitative demo subordinate to actual measured evidence.

## Runtime constraints

- Simulation only. Do not add or command real hardware in this project.
- Each native action must pass the shared governor hooks. No full uninterruptible
  native VLA chunk may bypass the step budget or terminal latch.
- New simulator instances are owned by the run. Never reset or terminate the
  user's earlier GPU assembly/BEHAVIOR workers or shared policy services.
- On a possibly executed command without a receipt: stop and reconcile; no retry.
- Native wall-clock checks are cooperative, not a certified real-time guarantee.
- No gain thresholds, clipping, source coordinates, or hidden evaluator shortcuts
  should be relaxed solely to obtain an impressive score.
- API calls need explicit opt-in and an explicit model/endpoint. Supply secrets
  through environment/private configuration. No keys in Git or JSON templates.
- Reserve budgets before sending. Unknown costs remain held. Each parallel worker
  must receive its own allocated sub-budget; no duplicating the whole budget.
- Do not run arbitrary shell/code generated by the actor. The command-planner
  interface is a trusted external program, not a sandbox security boundary.
