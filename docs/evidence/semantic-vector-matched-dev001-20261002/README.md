# Fresh Five-Case Vector Development Cohort

The roster is three sorting layouts (0,1,2) and two tower layouts (0,1):
**two task types and five unique task-layout cases**, not five distinct task
types. Each layout appears once per condition. This differs from the earlier
ten-row capacity wave, which repeated some layouts.

`semantic-vector-matched-dev001-plan.json` was written remotely before the
first motor-only comparison actions. It records source operator SHA-256,
provider identity, fixed roster, native seed0 singleton inference streams,
H50/15 cadence, device placement, native horizons and no retry/replacement.
The frozen production runtime remains unchanged. Exact experimental sources
are retained here. Proposed later condition configs are saved but are not
evidence those conditions ran; each must be bound before launch.

The two native simulator processes run concurrently on GPU0 and share one
pi0.5 runtime on GPU1. Rows that stop are removed from dispatch; their physics
continues globally within the family and terminal scores remain frozen.
This new execution cohort must not silently replace or pool historical serial
results. Rendering/reset parity with serial episodes is not established.

Condition order: original-only, task-plus-subtask, then subtask-only. Recovery
remains disabled. Keep every native failure, abstention, resource/API stop and
missing case. Use outcomes only after source/ACK/prompt/RNG audits. Broad task
generalization requires the later untouched held-out-family evaluation.

Large unique sensor payloads remain remote until separately backed up. Do not
retire them or shut down/destroy the rental based on these small public reports.
